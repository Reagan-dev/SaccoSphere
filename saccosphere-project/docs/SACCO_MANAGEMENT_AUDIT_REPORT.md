# SACCO Management — Production-Readiness Audit

Scope, as specified: (1) SACCO Configuration — creation, settings, M-Pesa payment config,
membership type, listing/verification; (2) RBAC — three-tier roles, granular per-resource
permissions, SACCO-scoped/platform-wide admin; (3) Member Management — application
workflow, custom SACCO fields, bulk import, member status/number; (4) SACCO Operations —
bulk SMS, system audit logging, ODPC data-access logging, compliance flagging.

Every claim below was traced to source. Where a claim could not be confirmed in code, it
is marked **unverified** rather than assumed handled.

---

## 1. Verdict: **Not Production Ready**

Four independent findings each meet the "money/security/data-loss" bar on their own
(#1, #2, #3, #4 in the table below): bulk member import can silently reactivate a
suspended/rejected member; the API endpoint that serves raw KYC ID/passport images has
zero access logging; M-Pesa Daraja/STK secrets render as plaintext, unmasked form fields
to any Django-admin staff user; and almost none of the sensitive admin actions in this
feature (role changes, application decisions, settings edits, SMS sends, imports,
dividend approvals) write an audit trail, despite the codebase already having a
ready-made, tested convention for this (`saccomanagement/audit_logger.py`) that simply
wasn't wired in. None of these require exotic conditions to trigger — they are default
behavior on the happy path.

## 3. Top blockers (priority order)

1. **Fix the bulk-import status-overwrite bug (#1).** `_import_member_row` must not force `status=APPROVED` on an existing `Membership` regardless of its current state — at minimum, skip or explicitly flag rows for members whose current status is `SUSPENDED`/`LEFT`/anything other than the expected pre-import state, rather than silently overwriting. This is a live path to reactivating members whose access was deliberately revoked.
2. **Add access logging to `KYCDocumentServeView` (#2).** It's the one endpoint that actually serves the raw ID/passport imagery over the API and currently no one can tell who viewed which document, when. Reuse `create_data_consent_log`/`DataAccessMixin`, already proven reliable elsewhere in this codebase.
3. **Stop exposing Daraja/M-Pesa secrets in plaintext admin form fields (#3).** Either add these three fields to `readonly_fields` with a masked display (e.g. show only last 4 characters) or move editing to a dedicated write-only action, so the decrypted value is never rendered back to a browser.
4. **Wire `log_audit()` into the write endpoints listed in #4** (roles, application review, settings, SMS, import, dividends, guarantor review). This is largely mechanical given the existing `AuditMixin`/`log_audit()` helper and its proven track record elsewhere in this same app.
5. **Add a last-admin-lockout guard to `RoleRevokeView` (#5)** — reject revocation of the last `SACCO_ADMIN` at a sacco or the last `SUPER_ADMIN` platform-wide, or require an explicit override.
6. ~~**Decide the fate of `RolePermission` (#6):** either implement real per-resource CRUD checks against it, or remove it from the schema/spec so the feature isn't documented as having something it doesn't.~~ **RESOLVED**: removed (migration `0008_remove_rolepermission`) — no near-term product requirement for finer-than-role-tier permissions existed to justify building real enforcement against it.
7. **Fix the rejected-application / stuck-`PENDING`-membership bug (#7)** and add an idempotency guard to `ApplicationReviewView` (#8) before either ships further changes in that view.
8. **Assign `member_number` somewhere on the live approval path (#9)** — currently unimplemented outside an unreachable dead pipeline.

## 4. Non-blocking hardening suggestions

- Add real type coercion/validation for custom SACCO field values against their declared `FieldType` (#11), and a SACCO_ADMIN-facing API to manage field definitions if that's intended to be self-service (#12).
- Wire `min_loan_amount`/`max_loan_amount`/`requires_guarantor`/`guarantor_type_allowed` into actual loan/guarantor decision logic, or remove them from the editable settings surface until they are (#13).
- Enforce `STAFF_ONLY` membership type in the join flow, or remove it as a choice if it's not meant to be enforced yet (#14).
- Wrap the `Sacco`/`SaccoSettings` dual-write in `transaction.atomic()` and reconsider whether `Sacco.registration_fee`/`loan_multiplier` should stay directly editable in `/admin/` now that `SaccoSettingsView` exists (#15).
- Decide `SUPER_ADMIN` behavior for `SaccoSettingsView` deliberately rather than leaving an apparent oversight (#16); add bounds validation to `SaccoSettingsSerializer` (#17).
- Add an `AppConfig.ready()`/Django system check that fails fast if `FIELD_ENCRYPTION_KEY` is missing/invalid, rather than discovering it lazily (#19).
- Either remove the dead `SMSCampaign.Status.QUEUED` value (#22) or use it as an actual pre-send state; add a `PARTIAL` campaign status and a remediation path for a task stuck in `SENDING` after retry exhaustion (#23); add API-layer throttling on send endpoints, not just the daily-limit check (#24).
- Delete the orphaned `saccomanagement/data_imports/` pipeline (#10) or wire it up deliberately — as-is it's dead code with its own test suite giving false confidence, and its coexistence with the live `import_utils.py` pipeline is a maintenance hazard.
- If "compliance flagging" is meant to be automated monitoring rather than a manual admin tool, build the detection logic that creates `ComplianceFlag` rows from real signals (payment failures, liquidity breaches, etc.) — right now it's schema + dashboard only (#25).
- Add test coverage for RBAC write endpoints (#27), application-review reject/idempotency (#28), and custom fields (#29) before making further changes to any of them.
